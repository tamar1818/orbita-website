# Webico — ციფრული სააგენტოს ვებსაიტი

მრავალგვერდიანი SaaS-სტილის საიტი ვებ-დეველოპმენტის, SEO-სა და ციფრული მარკეტინგის
სააგენტოსთვის. სრულად ქართულ ენაზე, ლიდების შეგროვების ფორმებით.

**სტეკი:** სუფთა HTML + CSS + JavaScript. ბილდი, `npm install` და დამოკიდებულებები
**საჭირო არ არის** — უბრალოდ გახსენით `index.html` ბრაუზერში.

## ლიდების ფორმები

საიტზე **13 ფორმაა** — ლიდის შეგროვების წერტილი ყველა გვერდზეა:

- მოკლე ფორმა (სახელი / ელფოსტა / კონტაქტი) — მთავარი გვერდის hero-ში და ყველა CTA-ბლოკში;
- სრული ფორმა (სახელი, კომპანია, ელფოსტა, ტელეფონი, სერვისი, ბიუჯეტი, შეტყობინება,
  თანხმობა) — `contact.html`-სა და სერვისების შიდა გვერდებზე.

რაც უკვე მუშაობს:

- ვალიდაცია ქართული შეტყობინებებით (ელფოსტა, ტელეფონი, სავალდებულო ველები);
- შეცდომის ჩვენება ველიდან გასვლისას და გასწორება წერის დროს;
- `honeypot` ველი სპამ-ბოტებისგან;
- გაგზავნის შემდეგ — მადლობის ეკრანი მომხმარებლის სახელით;
- `contact.html?service=seo` — ბმულით წინასწარ შერჩეული სერვისი ფორმაში.

### ფორმის მიმღებთან დაკავშირება

ახლა ფორმა **სადემონსტრაციო რეჟიმშია**: ვალიდაცია სრულად მუშაობს, მონაცემები კი
ბრაუზერის კონსოლში იბეჭდება. რეალურ მიმღებზე გადასართავად შეცვალეთ ერთი სტრიქონი
[`assets/js/main.js`](assets/js/main.js)-ის დასაწყისში:

```js
const FORM_ENDPOINT = "https://formspree.io/f/თქვენი-კოდი";
```

გამოდგება ნებისმიერი სერვისი, რომელიც JSON-ს `POST`-ით იღებს — Formspree, Web3Forms,
Getform, ან თქვენი საკუთარი backend. მონაცემები იგზავნება ასეთი სახით:

```json
{ "name": "...", "company": "...", "email": "...", "phone": "...",
  "service": "seo", "budget": "5000-12000", "message": "...",
  "consent": "yes", "page": "/contact.html", "source": "contact-page" }
```

## რა არის უკვე გათვალისწინებული

- **SEO:** უნიკალური `<title>` და `description` თითო გვერდზე, Open Graph, `canonical`,
  სემანტიკური სტრუქტურა, `sitemap.xml`, `robots.txt` და Schema.org მიკრომონიშვნა
  (`ProfessionalService`, `Service`, `ContactPage`).
- **წვდომადობა:** `lang="ka"`, კლავიატურით სრული ნავიგაცია, ხილული ფოკუსი,
  `aria-expanded` / `aria-controls` მენიუსა და აკორდეონზე, „კონტენტზე გადასვლის“ ბმული,
  `prefers-reduced-motion` მხარდაჭერა.
- **ადაპტურობა:** სამი გარდატეხის წერტილი (1040 / 880 / 620 px), მობილური მენიუ.
- **წარმადობა:** გარე დამოკიდებულებების გარეშე, SVG-იკონები კოდშივე, `font-display: swap`.
- **მდგრადობა:** JavaScript-ის გამორთვის შემთხვევაშიც მთელი კონტენტი ჩანს.

## CMS — მართვის პანელი

საიტს აქვს საკუთარი, ფაილებზე დაფუძნებული CMS. **ბაზა არ სჭირდება.**

### პირველი გაშვება

1. აიტვირთეთ ფაილები ჰოსტინგზე (PHP 8.1+).
2. გახსენით `https://webico.io/admin/` — გამოჩნდება ანგარიშის შექმნის ფორმა.
3. შეიყვანეთ მომხმარებელი და **მინიმუმ 10-სიმბოლოიანი** პაროლი.
4. პაროლი შეინახება მხოლოდ ჰეშის სახით `content/auth.php`-ში.

> `content/auth.php` და `content/leads.json` **განზრახ არ არის git-ში** —
> პაროლის ჰეშსა და კლიენტების პერსონალურ მონაცემებს რეპოზიტორიაში ადგილი არ აქვს.

### რა იმართება

| განყოფილება | რა |
|---|---|
| პროექტები | დამატება, რედაქტირება, წაშლა, დამალვა; ტექსტები, თეგები, ინსტრუმენტები, მოკაპი |
| ბლოგი | სტატიების დამატება/რედაქტირება/წაშლა, კატეგორია, ყდა, დაგეგმილი გამოქვეყნება (მომავალი თარიღი), მონახაზი |
| ფოტოები | ატვირთვა და წაშლა; მისამართის კოპირება პროექტში ჩასასმელად |
| ტექსტები | მთავარი გვერდისა და სხვა გვერდების საკვანძო წარწერები |

### დინამიკური და სტატიკური გვერდები

| გვერდი | სტატუსი |
|---|---|
| `/` (index.php) | დინამიკური — hero-ს ტექსტები და კლიენტების კარუსელი CMS-იდან |
| `/work` (work.php) | დინამიკური — პროექტების სია |
| `/work-<slug>` (project.php) | დინამიკური — თითოეული პროექტი |
| `/blog` (blog.php) | დინამიკური — სტატიების სია, კატეგორიების ფილტრი |
| `/blog/<slug>` (post.php) | დინამიკური — სტატია, სარჩევი, გაზიარება, მსგავსი სტატიები |
| `/sitemap.xml` (sitemap.php) | დინამიკური — პროექტები და სტატიები ავტომატურად ემატება |
| `/about`, `/services`, `/contact`, სერვისების გვერდები | **ჯერ სტატიკური** — ტექსტები ფაილშია |

სტატიკური გვერდების CMS-ზე გადაყვანა იგივე ხერხით ხდება: `.html` → `.php`,
ტექსტი `<?= T("key", "საწყისი") ?>`-ში, გასაღები `admin/view.php`-ის
`$TEXT_FIELDS`-ში.

### ბლოგი

სტატიები ინახება `content/posts.json`-ში და იმართება `/admin/` → ბლოგი.
ტექსტი შეიძლება დაიწეროს უბრალოდ (ცარიელი ხაზი = ახალი აბზაცი) ან HTML-ით:
`<h2>` ქვესათაურები ავტომატურად ხვდება სარჩევში. ტექსტი გამოქვეყნებამდე
სუფთავდება — სკრიპტები, `on*` ატრიბუტები, `javascript:` ბმულები და
iframe-ები იშლება. ყდის ფოტოს გარეშე ყდა ავტომატურად იხატება კატეგორიის
ფერითა და ხატულით.

### ჩატბოტი და შეხვედრების დაჯავშნა

- **ჩატბოტი** ყველა გვერდზეა (ქვედა მარჯვენა კუთხე). სვამს 8 მოკლე კითხვას
  (სერვისი, არსებული საიტი, ბიუჯეტი, ვადა, სახელი, ელფოსტა, ტელეფონი,
  დამატებითი ინფორმაცია) და ლიდს აგზავნის `api/lead.php`-ზე — ისევე, როგორც
  ფორმები. ლიდი ჩანს ადმინში („განაცხადები“, წყარო: `chatbot`) და მოდის ელფოსტაზე.
- **დაჯავშნა** — `/contact#booking`. კლიენტი ირჩევს დღეს და საათს, ორმაგი
  ჯავშანი გამორიცხულია. გუნდს მოდის შეტყობინება, კლიენტს — დადასტურება
  Google Calendar-ის ბმულით. ადმინში „შეხვედრები“: ჯავშნების სია, სტატუსი
  (ჩატარდა / გაუქმება — გაუქმებული დრო ისევ თავისუფლდება) და განრიგი
  (სამუშაო დღეები, საათები, ხანგრძლივობა, დაკეტილი თარიღები).
- **ელფოსტა:** ყველა შეტყობინება მიდის ადმინის „კონტაქტები → ელფოსტა“-ზე,

## პროექტები

24 პროექტის ბადე და შიდა გვერდები **ერთი ფაილიდან** გენერირდება:

პროექტები ახლა **ადმინიდან** იმართება (`/admin/` → პროექტები).
მონაცემები: `content/projects.json`. გენერატორი აღარ საჭიროა — გვერდები
დინამიკურად იხატება.

**მნიშვნელოვანი:** ცარიელი ველი გვერდზე საერთოდ არ ჩნდება. სანამ `summary`,
`challenge`, `solution`, `scope`, `stack` ან `result` არ შეგივსიათ, შესაბამისი
სექცია არ გენერირდება — ასე საიტზე არაფერი გამოგონილი არ ქვეყნდება.

მაგალითი:

```json
{
  "slug": "oribu", "name": "Oribu", "domain": "oribu.ge", "tone": "pink",
  "year": "2025",
  "summary": "ერთი-ორი წინადადება ბარათისთვის.",
  "challenge": "რა ამოცანა იდგა კლიენტის წინაშე.",

  "stack": ["WordPress"],
  "result": "გაზომილი შედეგი — მხოლოდ რეალური რიცხვები.",

```

### მოკაპები

რეალური მოკაპები (3:2, 1536×1024) ინახება `assets/img/work/`-ში სამ ვერსიად:
`<slug>.webp` (დიდი), `<slug>-sm.webp` (768px, ბარათებისთვის — `srcset`-ით
ავტომატურად გამოიყენება) და `<slug>-og.jpg` (1200×800, სოციალურ ქსელებში
გაზიარებისთვის). პროექტს, რომელსაც მოკაპი არ აქვს, საიტის მინიატურა
ავტომატურად ეხატება.

სასაქონლო ნიშნები არ გამოგვიყენებია. რეალური ლოგოებით ჩასანაცვლებლად

## ინტერაქტიული კომპონენტები

ყველა კომპონენტი სუფთა JavaScript-ითაა — გარე ბიბლიოთეკის გარეშე.

**კარუსელი** — `scroll-snap`-ზე აგებული. მარკაპი:

```html
<div class="carousel carousel--2" data-carousel>
  <div class="carousel__viewport" data-carousel-track>
    <div class="carousel__slide">…</div>
  </div>
  <div class="carousel__controls">
    <button data-carousel-prev>…</button>
    <div class="carousel__dots" data-carousel-dots></div>
    <button data-carousel-next>…</button>
  </div>
</div>
```

წერტილები ავტომატურად გენერირდება, ისრები ითიშება ბოლოებში, მუშაობს
კლავიატურის ისრებით და თითით გადაფურცვლით. `carousel--2` — ორი სლაიდი ერთდროულად.

**ფილტრი** — `data-filter-group` ღილაკები და `data-category` ელემენტები.
რაოდენობები ავტომატურად ითვლება, ცვლილება ეცნობება სკრინრიდერს `aria-live`-ით.

**გუნდის ბარათები** — `data-member-toggle` + `aria-expanded` გაშლადი ბიოგრაფიით.

**Mega-menu** — „სერვისები“ ხსნის ორსვეტიან პანელს: მარცხნივ სერვისები
აღწერებით, მარჯვნივ ტექნოლოგიები (WordPress, Shopify, Webflow, Lovable,
Custom code, Next.js/React, AWS, Figma).

```html
<li class="nav__item">
  <button data-mega-trigger aria-expanded="false" aria-controls="mega-services"
          data-nav-match="services">სერვისები</button>
  <div class="mega" id="mega-services"><div> … </div></div>
</li>
```

დესკტოპზე იხსნება hover-ითა და დაჭერით, მობილურზე — იშლება მენიუს შიგნით.
იხურება Esc-ით, გარეთ დაჭერით და ფოკუსის გასვლისას. ტექნოლოგიების ჩამონათვალი
რომ შეცვალოთ, დაარედაქტირეთ `.tools` ბლოკი — ფერი `--tint` ცვლადით იმართება.

> ⚠️ ნავიგაციის სტილები შეგნებულად `.nav__links > li > a`-ზეა მიბმული და არა
> `.nav__links a`-ზე — თორემ მაიუსკული და letter-spacing mega-ს შიგნითაც გაჟონავდა.

## სუფთა URL-ები

საიტი მუშაობს გაფართოების გარეშე: `/services`, `/about`, `/contact` და ა.შ.
ამას უზრუნველყოფს `.htaccess` (Apache / LiteSpeed — Hostinger):

- `/page.html` → `/page` — 301 გადამისამართება (დუბლიკატების თავიდან ასაცილებლად)
- `/index.html` → `/`
- ბოლო სლეშის მოცილება
- `http` → `https` და `www` → არა-`www`
- gzip შეკუმშვა, ქეშირება, უსაფრთხოების ჰედერები
- `ErrorDocument 404 /404.html`

> ⚠️ `.htaccess` მუშაობს Apache-სა და LiteSpeed-ზე (Hostinger-ის ჩათვლით).
> Nginx-ზე ან GitHub Pages-ზე საჭიროა ანალოგიური წესები სერვერის კონფიგურაციაში —
> წინააღმდეგ შემთხვევაში გაფართოებიანი ბმულები დაგჭირდებათ.

  `BreadcrumbList` და `FAQPage` — ბოლო ორი Google-ის რიჩ-შედეგებისთვის
